# HADO資料デザイン（hado-deck）

HADOの資料はすべてこのデザインシステムで作る。**PowerPointやGoogleスライドは使わず、HTML→PDF**で作る。
理由：編集・差し替えが効き、全ページの整合が機械的に揃い、Claudeが自分でレンダリングして確認できるため。

## 0. 最初にやること（環境確認）

このスキルのフォルダ（`SKILL.md` があるディレクトリ。以下 `$SKILL`）に、以下が入っている。

| ファイル | 用途 |
|---|---|
| `template.html` | CSS一式＋見本スライド6枚（表紙／KPI4連／2カラム+フロー／Before-After／持ち帰り3つ＋締め／Thank you） |
| `build.sh` | deck.html → PDF（Chrome headless）→ `preview/slide_NN.png`（PyMuPDF） |
| `assets/logo_black.png` `assets/logo_white.png` | HADO公式ロゴ |
| `examples/*.html` | 完成形の実例（登壇資料・社内締め会資料）。**構成と部品の使い方の参考にする**（画像ファイルは同梱していないので開いても画像は出ない） |

ビルドには **Google Chrome** と **python3 + PyMuPDF** が必要。作業開始時に次を確認し、無ければ入れる（ユーザーに聞かず自分で実行してよい）。

```bash
ls "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"   # 無ければ https://www.google.com/chrome/ を案内
python3 -c "import fitz" 2>/dev/null || pip3 install --user pymupdf
```

## 1. 作業手順

1. **フォルダを作る**：ユーザーの現在のディレクトリ直下に `<資料名>-deck/` を作り、`$SKILL/template.html` を `deck.html` として、`$SKILL/build.sh` と `$SKILL/assets/` をコピーする。
2. **構成を先に出す**：スライド一覧（1行1枚：番号・見出し・何を載せるか）をユーザーに提示し、OKをもらってから書く。ユーザーが「すぐ作って」と言ったら構成提示と制作を同時に進めてよい。
3. **deck.html を書く**：`<section class="slide">` を増減して中身を入れる。CSSはテンプレの `<style>` をそのまま使い、必要な部品だけ足す。
4. **ビルド**：`cd <資料名>-deck && ./build.sh deck.html <資料名>.pdf`
5. **全枚を目視**：`preview/slide_NN.png` を **1枚ずつ Read で開いて**、折り返し・はみ出し・空白・文字かぶりを直す。直したら再ビルドし、直した枚を再確認する。全枚OKになるまで繰り返す。
6. **納品**：PDFのパスをユーザーに渡す（SendUserFile が使えれば送る）。「差し替えたい枚と内容を言ってもらえればその場で直す」と添える。

## 2. ビジュアルルール（変えない）

- **キャンバス**：1280×720px、`@page{size:1280px 720px;margin:0}`。
- **色は3つだけ**：ネイビー `#0F1B33`（見出し・締め帯・表紙）／ブルー `#2457F5`（アクセント・強調・キッカー）／オレンジ `#FF6B2C`（注意・Point・数字の差分）。背景はオフホワイト `#F7F8FB`、カードは白。**他の色を足さない**（グラフの系列色も紺／青／橙／薄青 `#E8EEFF` でまかなう）。
- **フォント**：Hiragino Sans 1種。見出し h2 34px/800、本文14〜17px、数字は44〜64px/900 に `letter-spacing:-2px`。
- **全ページ共通の骨格**：上端6pxのグラデーションバー（`.topbar`）、右上に黒ロゴ（`.logo` 高さ18px）、左上にキッカー（`.kicker` ＝ 青チップの番号＋セクション名）、左下 `© 2026 HADO, Inc.`、右下ページ番号（`.pageno`）。
- **カードは `.card` 1種類**（白・角丸16px・薄い影・1px罫）。中身は「見出し／本文／Point引用（`.quote`：オレンジ左罫の薄橙帯）」。
- **表紙・扉・締め**は紺のラジアルグラデーション（`.cover` / `.sec` / `.divider`）＋青とオレンジのぼかし光＋白ロゴ。表紙タイトルは短いコピー（例「録れば、動く。」「次の海へ、出航。」）。「〜を"資産"に変える」のような説明的タイトルは不可。
- **締めのコピーは表紙と呼応**させる。
- 見出し h2 は **1行に収める**（全角およそ32文字まで）。2行になるとレイアウトが崩れる。
- ページ内に空白が余ったら要素を足すのではなく、余白として許容するか、紺の締め帯（`.band`）で1文置く。

## 3. 型の部品（テンプレと examples にある）

| 用途 | 部品 |
|---|---|
| 数字で見せる | `.kpis` ＋ `.card.kpi`（3〜4連） |
| 流れ・手順 | `.flow-h` の `.st`（青 → 紺 `.hot` → 紺 → 橙 `.acc`）。文字は短い語にして `word-break:keep-all` |
| 本文＋右に実画面 | `.two`（左 `.card.main`・右 `.side` に `.shot` と `.tips`） |
| 効果 | Before/After 横棒（`.s8`）＋KPIカード |
| 比較・棲み分け | `table.cmp`（ヘッダ紺、自社列は青 `.us`） |
| 持ち帰り／アジェンダ | 番号付き3項目（`.list .it`）＋紺の締め帯 |
| セクション扉 | `.sec`（大きな薄い番号＋見出し＋チップ） |
| 実画面・写真 | `.shot` / `.browser`（ブラウザ枠）/ `.phone`（スマホ枠） |
| 提携先ロゴ | `.brands .brand`（ロゴ高さ40〜48px） |

## 4. コンテンツルール

- **ロゴ・数字・画面は本物を入れる**。ロゴは公式サイトから取得、数字は実データ、画面は実スクショか「再現画面」と明記したモック。
- 「差込予定」「案」「試作」「TBD」のラベルを残したまま納品しない。分からない数字はユーザーに聞くか、その要素ごと外す。
- 会社の自称は **「求職者送客プラットフォーム HADO」**。「人材紹介会社」はクライアント側の呼称。
- 用語：求職者送客の窓口（本体事業）／求職者送客クラウド（リード課金の新サービス・toC名はソクレキ）／ハックツ就職・ハックツ新卒（集客ブランド）。
- 写真を使うときは、暗ければ PIL で明るさ・シャドウを持ち上げてから使う（白飛びさせない）。段ボールや台車など生活感が写る写真は避ける。
- 他社の漫画・アニメ・写真は転載しない。必要なら gpt-image-2 等でオリジナルを生成する。
- 公開リポジトリに置く資料には、社外秘の単価・顧客名・個人名を入れない。

## 5. 文字崩れの常習と対処

- フロー（`.flow-h .st`）の文字列が長いと折り返す → 語を短くする、`word-break:keep-all`。
- `.band` や `.quote` の1文が長いと2行目に1〜3文字だけ残る → 文を削る。
- 画像入りグリッドで親が伸びてフッターに重なる → 親に `min-height:0`、画像は `object-fit:cover`。
- `.placeholder` 内の small は `flex-direction:column`。
- 2列カードの中身が少なくて下が空く → `margin-top:auto` で下に一言ボックス（お願い・Point）を置く。

## 6. ユーザーへの伝え方

- 途中経過も納品も日本語。
- 納品時は「何枚・どこにあるか・自分で判断した点・確認してほしい点」を短く。
- 直しの依頼は枚数と内容を聞くだけで済むようにする。
